# Contributing

1. Trabaja en una rama con el identificador de la iniciativa.
2. Mantén cambios acotados y actualiza el changelog del componente afectado.
3. No incluyas secretos, artefactos de npm/Maven, evidencias ni dumps.
4. Ejecuta las pruebas del componente, `git diff --check` y las validaciones de
   contrato aplicables.
5. Describe migraciones, compatibilidad, rollback y riesgos en el pull request.

Las convenciones detalladas están en [`docs/git/`](docs/git/README.md). La
aprobación formal de gobierno permanece pendiente de revisión del equipo.
